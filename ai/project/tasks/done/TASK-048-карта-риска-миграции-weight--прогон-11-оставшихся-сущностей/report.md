# Отчёт TASK-048 — карта риска миграции weight

## Резюме

Карта достроена по всем 15 сущностям. **Миграция меньше и безопаснее, чем считалось.**

Главное — в двух числах:

- **под угрозой 13 файлов**, все в одной фиче `weighing`;
- **10 из 14** сущностей руками не правились ни разу → перезаписываются пакетно, без разбора.

И одна поправка: **числа конфликтов в разведке 2026-07-28 завышены ровно вдвое**.

## Поправка к унаследованным числам (важное)

Части 1-2 разведки считали конфликты по числу `✗`-строк в выводе `generate-entity --human`.
Оказалось, **CLI печатает отчёт о конфликтах дважды** — потоком и повторно в сводке
`FAILED / Errors (2)`. Заголовок `Обнаружено конфликтов: N` всё это время сообщал правду.

| Величина | Части 1-2 | **Реально** |
| --- | --- | --- |
| конфликтов на сущность | 38 | **19** |
| `configuration` | 46 | **23** |
| всего по проекту | ≈570 | **271** |

Проверка, снявшая вопрос: `19 + 19 + 23 + 19 = 80` — ровно то `B`, которое часть 2 посчитала
для четырёх сущностей. Значит **множества файлов у предшественника верны**, завышен только
счётчик и экстраполяция; все выводы про пересечение A ∩ B остаются в силе.

Дефект вывода заведён как
[BUG-031](../../../bug-reports/031-generate-entity-duplicates-conflict-report-in-output.md).

## Карта риска

Множество **A** (файлы с точечными правками) воспроизведено по методике части 2 и совпало
с ней число в число: 389 codegen-файлов, 51 коммит их трогал (12 массовых / 39 точечных),
**A = 41**.

**B = 271 уникальный файл.** Сумма по сущностям равна объединению — сущности не делят между
собой конфликтующие файлы.

**A ∩ B = 13 файлов, все в `weighing`.** Ни один не имеет региона `:base` → при
подтверждённой перезаписи затирается целиком. Пофайловый список с происхождением правок —
в probe-документе, часть 4, факт 15.

### Что из этих 13 ценно

- **sync-логика и subscription-guard** (`ac464554`): `weighing_repository_impl`,
  `weighing_data_providers`, `weighing_remote_data_source`, `weighing_state_providers` —
  терять нельзя;
- **печать талона** (`cb5c3751`): `weighing_entity_extension`;
- **`*_table_extension` / `*_model_extension`** у `driver`/`vehicle`/`weighing` (`ccde34ab`,
  «UI весовой программы») — похоже на доменные хелперы, смотреть глазами;
- **три `*_state_providers`** у `driver`/`vehicle`/`contractor` — коммит `bc6a7a1f` с
  сообщением «work». Происхождение непрозрачное: смотреть диффом, а не по сообщению.

### Сущности с пустым пересечением — перезаписывать пакетно

```text
cargo_type, configuration, correction_button, custom_field, device_owner,
subscription, terminal_device, terminal_set, weighing_correction, weighing_photo
```

199 файлов, backup включён по умолчанию (`.codegen/backup/<timestamp>/`).

### `custom_field_value` — не прогоняется как миграция, и это не пропуск

YAML на сервере есть, во flutter **ни одного файла** — на клиент никогда не генерировалась.
Прогон дал exit 0, ноль конфликтов, 24 файла создано. Это сценарий TASK-047 (новая сущность),
а не регенерация. Зафиксировано отдельно, как требовал контракт.

## Побочный результат для TASK-049

Замер по всему B: **merge 44 (16%) / full-replace 227 (83%)**.

Регион `:base` несут ровно три типа файлов: `*_dao`, `*_repository` (domain-интерфейс),
`*_local_data_source`.

**Ни один из 13 файлов под угрозой не относится к защищённым типам.** Рвётся именно то, что
`:base` не покрывает: `*_extension`, `*_state_providers`, `*_data_providers`,
`repository_impl`, `remote_data_source`. Это готовый приоритетный список для TASK-049 —
задача получает не только обоснование, но и адрес.

## Методика (воспроизводима)

1. Копия weight — `git worktree add --detach`, имя папки обязано быть `weight`.
2. **B** — пути из вывода `generate-entity` при конфликте, **с дедупликацией**
   (`grep "^  ✗ " | sed 's/^  ✗ //' | sort -u`) — иначе BUG-031 удвоит.
3. **A** — codegen-файлы (маркер `// manifest:`) из коммитов, трогающих <10 codegen-файлов.
   ⚠ `git grep` в detached-worktree маркер не находит (причина не выяснена) — использовать
   обычный `grep -rl` по `weight_flutter/lib`, он даёт 389.
4. **A ∩ B** — искомое; merge/full-replace определяется наличием `generated_start:base`.

Маппинг «сущность → feature» неочевиден и определялся по факту наличия
`features/*/data/datasources/local/tables/<entity>_table.dart`:
`terminal_device`/`terminal_set` → `terminal`, `weighing_correction` → `correction`,
остальные weighing-сущности → `weighing`.

## Риски / Заметки

- Задача read-only: guard fail-closed, при конфликтах не записано ни одного файла.
  Единственная запись — прогон `custom_field_value` (конфликтов нет → файлы создались);
  копия после этого очищена, `git status` пуст.
- Копия weight на HEAD `1d5f7c0`, отстаёт от оригинала на 21 коммит. Дельта — рукописные
  слои вне зоны генератора (проверено в TASK-047), на карту риска не влияет.
- Порог «<10 файлов = ручная правка» — эвристика. Пограничные коммиты глазами не
  просматривались: при 13 файлах в пересечении дешевле посмотреть диффы самих файлов на
  шаге миграции, чем перепроверять классификацию коммитов.
