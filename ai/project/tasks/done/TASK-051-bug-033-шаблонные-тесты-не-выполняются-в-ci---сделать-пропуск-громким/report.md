# Отчёт TASK-051 — BUG-033: шаблонные тесты молча не выполнялись в CI

## Резюме

**Иллюзия покрытия убрана; защиты шаблонов в CI по-прежнему нет — и это решение владельца,
а не недоделка.**

Было: 31 тест из 468 на ubuntu-раннере уходил в `pending`, среди них гарды тихой порчи данных
(TASK-028 LWW skip-stale) и BUG-001 (`ref.mounted`). CI зелёный, «468 тестов» звучит как
покрытие, которого нет. Именно так BUG-032 прожил месяцы.

Стало: пропущенное **видно**, растёт **красным**, и локально пропуск можно запретить.

## Почему не сделано «правильное» решение

Оба очевидных пути упираются не в технику, а в решение владельца — факты проверены:

| Вариант | Блокер |
| --- | --- |
| checkout шаблонов в CI | **`t115` PRIVATE**, а `code-generator` **PUBLIC** → нужен PAT/deploy-key приватного репо в публичном workflow |
| вендорить фикстуру в репо | это **публикация фрагментов приватного** t115 в публичном репо |
| — | у **`simplified` вообще нет remote** → первый вариант для него недоступен в принципе |

Поэтому задача сознательно сделала то, что от решения не зависит. Работа с секретами и
публикация приватного содержимого были прописаны в STOP-gates и не выполнялись.

## Изменения

- `+ src/test/helpers/templates.ts` — единый резолв (`CODEGEN_TEMPLATES_PATH`, дефолт
  `G:/Templates`), `templateAvailable`, `skipUnlessTemplate`, `templatesRequired`.
  Пути отдаются в forward-slash: так было в заменяемых константах, и часть тестов их
  сравнивает — `path.join` на Windows дал бы `\` и сломал drop-in замену.
- `+ src/test/generators/template_coverage.test.ts` — канарейка: **всегда** исполняется,
  печатает проверенное/пропущенное, при `REQUIRE_TEMPLATES=1` роняет прогон.
- `~ 4 шаблонных теста` (`enum_parse_template_parity`, `local_apply_lww_guard`,
  `session_manager_ref_mounted`, `state_providers_ref_mounted`) — переведены с
  захардкоженных `G:/Templates/...` на helper. Это предпосылка для любого будущего варианта:
  теперь окружение способно подсунуть шаблоны.
- `~ .github/workflows/test.yml` — вывод pending + падение при превышении `PENDING_BASELINE=31`.
- `~ AGENTS.md` — раздел «CI не проверяет шаблоны»: норма локального прогона перед правкой
  шаблона.

## Тесты — проверено в четырёх режимах, а не в одном

```text
шаблоны есть,  обычный режим  → 470 passing,  0 pending, exit 0
шаблонов нет,  обычный режим  → 439 passing, 31 pending, exit 0
                                 канарейка печатает: «ПРОПУЩЕНЫ: t115, simplified»
шаблонов нет,  REQUIRE_TEMPLATES=1 → exit 9   (падает, как и должен)
шаблоны есть,  REQUIRE_TEMPLATES=1 → 470 passing, 0 pending, exit 0
```

Режим «шаблонов нет» имитирован через `CODEGEN_TEMPLATES_PATH` на пустой каталог — то есть
поведение CI воспроизведено локально, а не предположено.

Прочее: `npm run compile` clean, `npm run lint` **0 errors / 18 warnings** (baseline),
`task.py lint` — ошибок нет.

Тестов стало **470** (было 468): +2 канарейки. Число pending на раннере не изменилось — 31,
поэтому `PENDING_BASELINE=31` верен.

## Риски / Заметки

- **`PENDING_BASELINE` — ручная константа.** Если пропущенных станет меньше (шаблоны в CI),
  CI напечатает notice с просьбой опустить baseline, но не упадёт. Это осознанно: падать
  из-за роста покрытия — плохо.
- **Канарейка не заменяет защиту.** Она сообщает, что не проверено, но не проверяет сама.
  Пока владелец не выберет вариант, шаблоны защищены только локальным прогоном.
- **Норма локального прогона держится на дисциплине**, не на автоматике. Записана в
  AGENTS.md, но выполнение никто не форсирует — это честное ограничение, а не решение.

## Статус

Готово. Остаток BUG-033 (шаблоны в CI) вынесен владельцу с фактами по приватности.
