# TASK-049: миграция шаблонов на merge-дисциплину (`:base`-регионы в full-replace файлы)

> Второй этап ADR-0007 (первый — guard, закрыт TASK-042/043). Поглощает **BUG-013** и
> **BUG-007** — они об одном и том же: шаблоны без маркеров.
> **Это главное улучшение генератора по существу.** См. обоснование ниже.

## Цель

Сделать регенерацию на живом проекте безопасной *по умолчанию*, а не только «громкой».

Сегодня из ~38 файлов сущности только **6 — merge** (имеют регион `:base`), остальные
**32 — full-replace**: любой дописанный руками метод в `repository_impl.dart`,
`usecases.dart`, `*_data_source.dart` при регенерации исчезает целиком. Guard из TASK-042
теперь про это предупредит, но выбор у пользователя бинарный — не генерировать либо потерять.

С `:base`-регионом кастом снаружи региона переживает регенерацию автоматически, и конфликт
не возникает вовсе.

**Замер, на котором основана задача** ([weight-migration-probe](../../docs/weight-migration-probe-2026-07-28.md)):
на реальном проекте 84% конфликтующих файлов — full-replace.

## Не-цели

- НЕ делать patch-only постоянным режимом (отклонено там же).
- НЕ решать правку внутри `:oneToManyMethods` (BUG-030) — отдельная тема.
- НЕ менять guard/ledger (TASK-042/043 закрыты, их контракт не трогать).

## Порядок работы (важно)

Миграция **инкрементальная, по файлу**, а не одним махом:

1. Выбрать файл-шаблон, определить границу «машинное / пользовательское».
2. Обернуть машинную часть в `// === generated_start:base ===` / `generated_end:base`.
3. Прогнать `create-project` + `generate-entity` + `verify` на свежем `t<N>`.
4. Убедиться, что вывод для чистого проекта **не изменился** (diff против предыдущего `t<N-1>`).
5. Следующий файл.

Порядок файлов — по убыванию пользы: сначала те, куда чаще всего дописывают руками
(`repository_impl`, `usecases`, `*_local_data_source`, `*_remote_data_source`), потом
остальные.

## Заметки по реализации

- Шаблон t115 — **отдельный git-репо** (`devabacus/t115`, есть remote). Коммит через
  inline `-c safe.directory=G:/Templates/flutter/t115`, push отдельно и только по слову владельца.
- `simplified` — git-репо **без remote** + pre-existing dirty state владельца. Не коммитить без указания.
- Граница региона — вопрос дизайна, а не механики: слишком широкий `:base` = кастому негде
  жить; слишком узкий = машинный код снаружи и рассинхрон при эволюции шаблона. При сомнении
  — остановиться и спросить, а не решать молча.
- Полезный ориентир — те 6 файлов, где `:base` уже есть: посмотреть, как проведена граница там.
