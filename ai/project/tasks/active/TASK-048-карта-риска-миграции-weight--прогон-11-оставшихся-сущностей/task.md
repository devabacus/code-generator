# TASK-048: карта риска миграции weight (прогон 11 оставшихся сущностей)

> Достроить то, что разведка сделала для четырёх сущностей из пятнадцати.

## Цель

Получить полный список файлов, где регенерация weight уничтожит ручную работу — чтобы
миграция перестала быть прыжком в темноту.

Разведка ([weight-migration-probe](../../docs/weight-migration-probe-2026-07-28.md))
проверила 4 сущности из 15 и нашла пересечение «правилось руками» × «перезапишет генератор»
= **6 файлов, все в `weighing`**. У `subscription`, `terminal_device`, `configuration`
пересечение **пустое**.

Осталось 11 сущностей: `device_owner`, `terminal_set`, `cargo_type`, `contractor`,
`correction_button`, `custom_field`, `custom_field_value`, `driver`, `vehicle`,
`weighing_correction`, `weighing_photo`.

## Не-цели

- НЕ мигрировать и НЕ перезаписывать ничего — задача аналитическая, read-only.
- НЕ менять генератор.
- НЕ решать, что делать с найденными файлами (это следующий шаг, по фактам этой задачи).

## Scope

Разрешено: прогоны CLI в worktree-копии weight, дописывание
`ai/project/docs/weight-migration-probe-*.md`.
Запрещено: любые записи в оригинальный weight; коммиты в репо weight.

## Методика (воспроизвести ту же, что в части 2 разведки)

1. **A** — файлы с ручными правками: codegen-файлы (маркер `// manifest:`) из коммитов,
   трогающих <10 codegen-файлов (порог отделяет ручную правку от массовой регенерации).
2. **B** — файлы зоны перезаписи: пути из вывода `generate-entity` при конфликте
   (guard fail-closed, ничего не пишет).
3. **A ∩ B** — искомое. Для каждого файла пересечения дополнительно определить:
   merge (есть `:base`) или full-replace, и что за правки (`git log`).

Маппинг «сущность → feature» неочевиден (`device_log` → `device_logs`,
`terminal_device` → `terminal`) — сверять по факту наличия каталога.

## Критерии приёмки

- [ ] Все 11 сущностей прогнаны, число конфликтов зафиксировано по каждой
- [ ] Для каждой посчитано пересечение A ∩ B
- [ ] Итоговая таблица: сущность / конфликтов / под угрозой / merge vs full-replace
- [ ] Для каждого файла под угрозой — происхождение правки (сообщение коммита) и вердикт «ценно / регенерация»
- [ ] Явно перечислены сущности с **пустым** пересечением — их можно перезаписывать пакетно
- [ ] Результат дописан в `weight-migration-probe-*.md`
- [ ] Сущность, которая не прогоняется (валидация, отсутствие feature) — зафиксирована с причиной, а не пропущена молча

## Заметки по реализации

- Прогон безопасен: при конфликтах guard не пишет ни одного файла (проверено).
- Порог «<10 файлов = ручная правка» — эвристика. Пограничные коммиты (5–9 файлов)
  просматривать глазами, а не доверять числу.
- Часть правок в истории — регенерации прошлыми версиями генератора; отличать по
  сообщению коммита и по тому, менялся ли файл вместе с десятком соседей.
