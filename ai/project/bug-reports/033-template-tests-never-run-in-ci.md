# BUG-033: 31 тест из 468 никогда не выполняется в CI — все шаблонные гарды мертвы на общем гейте

**Статус:** OPEN (с 2026-07-30)
**Severity:** **High (процессный)** — гейт, на который все полагаются, не проверяет шаблоны
**Нашёл:** TASK-050, при сверке локального прогона с CI

## Симптом

Числа расходятся, и расхождение ровно на шаблонных тестах:

```text
локально (Windows, G:/Templates на месте):  468 passing,   0 pending
CI (ubuntu-latest, шаблонов нет):           437 passing,  31 pending
```

**31 тест (6.6%) на общем гейте не исполняется вообще.** Они помечаются pending и не
влияют ни на зелёный статус, ни на merge.

## Что именно не проверяется

Четыре файла читают шаблоны по **абсолютным путям** `G:/Templates/...`:

| Файл | Что охраняет |
| --- | --- |
| `generators/local_apply_lww_guard.test.ts` | **TASK-028** — LWW skip-stale guard. Его отсутствие = **тихая порча данных** при cross-device pull |
| `generators/state_providers_ref_mounted.test.ts` | **TASK-025 / TASK-032** — `ref.mounted` в state_providers (BUG-001) |
| `generators/session_manager_ref_mounted.test.ts` | **TASK-033** — `ref.mounted` в session_manager, оба шаблона |
| `generators/enum_parse_template_parity.test.ts` | **TASK-050 / BUG-032** — комплектность enum-хелпера |

То есть тесты, защищающие **самые тяжёлые из закрытых дефектов** (тихая порча данных,
Ref-disposed), на CI молчат. Зелёный CI ничего не говорит о состоянии шаблонов.

## Почему это важно, а не косметика

BUG-032 — прямая демонстрация последствий. Фикс TASK-027 доехал до `simplified` и не доехал
до `t115`; ни один автоматический гейт этого не заметил, дефект прожил месяцы и всплыл только
при ручном разборе чужой задачи. Мой новый parity-тест этот класс ловит — **но только на
машине владельца**, потому что сам попадает в те же 31 pending.

Итог: правка шаблона сегодня защищена ровно настолько, насколько кто-то помнит прогнать
тесты локально. Это не гейт, это привычка.

## Причина

Шаблоны лежат **вне репозитория** (`G:/Templates/flutter/{t115,simplified}`), пути в тестах
захардкожены абсолютными. На раннере каталога нет → guard'ы уводят тесты в pending.

Поведение guard'ов само по себе корректно: без шаблонов тест обязан не падать, а
воздержаться. Дефект не в них, а в том, что **на CI шаблонов нет и их никто туда не приносит.**

## Варианты решения

1. **Checkout шаблонов в CI.** `t115` — публичный репо `devabacus/t115`, checkout возможен.
   ⚠ **`simplified` remote'а НЕ имеет** (локальный git-репо на машине владельца) — для него
   этот путь закрыт, пока не появится remote. То есть вариант закрывает половину.
2. **Вендорить минимальную фикстуру шаблона в репо** (`src/test/fixtures/templates/…`) —
   только те файлы, которых касаются гарды. Работает для обоих шаблонов и не зависит от
   remote'ов. Цена — фикстуру надо синхронизировать с настоящим шаблоном, иначе она сама
   протухнет (и это уже другой класс дефекта).
3. **Отдельный job «template checks», запускаемый только на self-hosted / вручную** — честно
   разделяет «универсальные тесты» и «тесты шаблона», но не даёт защиты по умолчанию.
4. **Сделать pending видимым:** минимум — печатать в CI число pending и падать, если оно
   выросло. Не решает проблему, но снимает иллюзию «468 зелёных».

Вариант 4 дёшев и полезен при любом из первых трёх.

## Обходной путь сейчас

Перед любой правкой шаблона гнать mocha **локально** и сверять: должно быть
**468 passing, 0 pending**. Ненулевой pending на машине владельца = шаблоны не найдены,
тесты не проверили ничего.
