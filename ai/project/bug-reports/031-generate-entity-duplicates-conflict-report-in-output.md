# BUG-031: `generate-entity` печатает отчёт о конфликтах дважды

**Статус:** OPEN (с 2026-07-29)
**Severity:** Low (DX) — но с доказанным эффектом на замеры
**Нашёл:** TASK-048, прогон 15 сущностей weight

## Симптом

При fail-closed preflight (`--human`) полный отчёт о конфликтах — заголовок, все пути,
все диффы, подсказка про `--overwrite-existing` — выводится **два раза**:

1. потоком, блоком `ERROR: Обнаружено конфликтов: N ...`;
2. повторно в финальной сводке `FAILED: generate-entity` → `Errors (2):`.

Для сущности с 19 конфликтами это ~500 строк вместо ~250. Пример (`subscription`):

```text
строка   8:  ✗ .../subscription_event_adapter.dart      ← первый список
строка 509:  ✗ .../subscription_event_adapter.dart      ← тот же файл, второй список
```

## Почему это не только косметика

Дублирование **уже привело к ошибке в замерах**. Разведка 2026-07-28
([weight-migration-probe](../docs/weight-migration-probe-2026-07-28.md), части 1-2) считала
конфликты по числу `✗`-строк и получила **38 на сущность** и экстраполяцию **≈570 файлов**.

Реальные числа ровно вдвое меньше — **19** и **271**. Заголовок `Обнаружено конфликтов: N`
всё это время сообщал правду, но глазами читался список, а он задвоен.

Сверка, снявшая вопрос: `19+19+23+19 = 80` — ровно то `B`, которое та же разведка посчитала
для четырёх сущностей корректно. То есть множества файлов были верны, завышен был только
счётчик.

## Причина (гипотеза, не проверена в коде)

Похоже на общий механизм CLI: ошибки и стримятся по ходу, и попадают в итоговый блок
`Errors (N)`. Для коротких сообщений это незаметно и даже полезно; для многострочного
отчёта с диффами — удвоение простыни.

## Как воспроизвести

```bash
node out/adapters/cli/index.js generate-entity \
  --yaml "<project>/<p>_server/lib/src/models/<f>/<e>.spy.yaml" \
  --feature-path "<project>/<p>_flutter/lib/features/<f>" \
  --workspace "<project>" --human > out.log 2>&1

grep -c "^  ✗ " out.log                                  # → 2 × реального числа
grep -oE "Обнаружено конфликтов: [0-9]+" out.log | head -1   # → реальное число
```

Нужен target-проект без `.codegen/ledger.json` (иначе конфликтов не будет).

## Предлагаемое решение

Печатать многострочный отчёт о конфликтах **один раз**. Варианты:

- не дублировать длинные ошибки в итоговом `Errors (N)` — там оставить одну строку-резюме
  («конфликтов: 19, подробности выше»);
- либо наоборот: убрать потоковый блок, оставив только сводку.

Первый вариант предпочтительнее: пользователь видит диффы по ходу, а в конце — краткий итог.

## Обходной путь до фикса

Верить **заголовку** `Обнаружено конфликтов: N`, а не числу `✗`-строк.
Для списка путей — дедуплицировать: `grep "^  ✗ " log | sed 's/^  ✗ //' | sort -u`.
