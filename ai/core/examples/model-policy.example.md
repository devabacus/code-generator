# Model policy проекта (пример ФОРМЫ, без имён)

> Человекочитаемый референс формы. Машинного `model-policy.yaml` не будет: TASK-023 закрыта
> по ADR-0004 — оперативная привязка субагента к модели живёт во frontmatter самого агента
> (`.claude/agents/*.md`, поле `model:`). Этот Markdown не парсить кодом.

Референс формы для `ai/project/docs/model-policy.md`. Привязка capability tiers
(см. `core/docs/workflow.md` → «Политика моделей») к конкретным моделям — проектное решение;
core этот файл не перезаписывает.

**Привязки tier→модель и конкретных model ID в `core/` нет и не появляется.** Единственное
место в репозитории, где они живут, — `ai/project/docs/model-policy.md`; при смене модельного
парка правится только он. (Имена вендоров как псевдонимы участников дискуссии в
`core/discussions/` — не привязка tier→модель и под правило не подпадают.)
Ниже — форма таблицы: колонку «Модель» заполняет проект у себя, не здесь.

| Tier | Модель | Примечание |
| --- | --- | --- |
| `frontier` | *(заполняет проект)* | Только главная интерактивная сессия владельца, по явному выбору (`/model`). Субагентам запрещён |
| `standard` | *(заполняет проект)* | Default для executor/reviewer-субагентов |
| `mechanical` | *(заполняет проект)* | Поиск, массовые правки, первичное чтение |
| `independent_reviewer` | *(заполняет проект)* | Обязательно ДРУГОЙ вендор, чем у writer'а; недоступен → fail-closed (TASK-011) |

Правила из core (напоминание): субагентам tier/модель назначается явно; наследование
`frontier` запрещено; ночной оркестратор — скрипт, не модель.
